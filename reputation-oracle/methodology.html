Score bands

What a score means

All chains use the same five bands. A score of 0 is reserved for sanctioned addresses; otherwise scores are bounded 1–100. Wallets with too few transactions to score reliably return a distinct INSUFFICIENT_DATA status with score: null — not a low score.

ℹ
Status resolution order Every query resolves in this order: (1) Sanctions screening — a match returns BLACKLISTED immediately, score 0, regardless of transaction history. (2) Data sufficiency — if the wallet clears sanctions but has too few transactions, returns INSUFFICIENT_DATA with score: null. (3) Behavioral score — only wallets that clear both checks receive a numeric score and a band label.

INSUFFICIENT_DATA thresholds by chain: EVM — fewer than 5 Ethereum mainnet transactions; Stellar — fewer than 3 ledger transactions; XRPL — fewer than 3 ledger transactions; Solana — fewer than 5 transactions.

Response format when INSUFFICIENT_DATA:
{ "status": "INSUFFICIENT_DATA", "score": null, "reason": "transaction_count_below_threshold", "threshold": 5, "actual": 2 }

Cryptographic provenance

How signed scores work

The /signed/ endpoints return an ECDSA-P256 signature over the score payload, verifiable against the Nulucre public key.

01
Score computed
All signals fetched and weighted. Final score and status determined.
02
Payload assembled
wallet, score, status, and timestamp serialized to JSON, then base64-encoded.
03
ECDSA-P256 signed
SHA-256 digest signed with Nulucre's private key using IEEE P1363 encoding.
04
Verify
Public key available at nulucre.com/.well-known/jwks.json. Signature is in the proof field of the response.
Validation status

What Nulucre is today — and what it will be

Nulucre is a deterministic, transparent, sanctions-screened signal. It is not yet a validated predictor of counterparty risk. The distinction matters.

✓
What Nulucre can claim today

Deterministic: The same wallet address returns the same score for the same on-chain state. The formula is public and auditable at this page.

Tamper-resistant inputs: Scores are computed from on-chain data — transaction history, wallet age, asset holdings — that cannot be altered retroactively.

Sanctions-screened: Every query runs real-time checks against OFAC SDN, OFAC Non-SDN, EU Financial Sanctions, and UN Security Council lists before a behavioral score is returned.

Agent-native: $0.001 USDC per query via x402 micropayments. No accounts, no API keys, no human provisioning required.

Honest about uncertainty: Wallets with too few transactions return INSUFFICIENT_DATA rather than a misleading low score.
ℹ
What the validation report will establish

Determinism and transparency do not equal accuracy. A scoring formula can be public and still be a poor model of trustworthiness if the wrong signals are weighted. The only way to establish predictive validity is to compare scores against outcomes.

A prospective cohort was started on October 20, 2026. Every paid query is logged with wallet, chain, score, status, and signal breakdown. In 90 days — approximately January 18, 2027 — those initial scores will be compared against actual wallet behavior during the observation window.

The validation report will answer: did high-scoring wallets behave more reliably than low-scoring ones? Until that report is published with real outcome data, treat Nulucre scores as one useful, cheap, transparent input — not a proven predictor.
→
Use Nulucre today if: you need a fast, cheap, sanctions-screened signal before a low-stakes agent transaction and want deterministic, auditable scoring.

Wait for the validation report if: you need a proven predictor of counterparty reliability for high-stakes decisions. That document will exist in January 2027.
